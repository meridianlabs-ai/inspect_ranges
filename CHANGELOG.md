## Unreleased

- The blocking signal's echo no longer leaks when a capture races it. The scrub used to run on the sliced delta, and a capture landing mid-echo of a WRAPPED suffix handed the next read a bare channel-name fragment no pattern can anchor (measured live under a wedged foreground ssh). Reads now scrub the full capture first, where every wrap and column is intact, strip any trailing not-yet-complete suffix partial, and slice deltas between those stable views, so no form of the suffix can straddle a read boundary. Ordinary output that merely resembles the suffix start at a racing capture's edge is emitted one read later, never lost.

- Two robustness debts from the build arc are paid. The capture subprocess bound rises from a flat 300 s to an hour: capture commands move realized-image-sized files, and the old bound killed two otherwise-green 75-minute builds at their final step when concurrent captures contended for IO; the bound's only job is catching a hung command, and a false kill costs a full rebuild while late hang detection costs wall-clock, so it errs long. And the build registers ownership BEFORE it leases rather than at first boot: a death in the lease-to-boot window used to leave a CID lease nothing could prove ownership of, the one gap in the reclaim's three signals, and record-then-lease is the order that closes it entirely (a record without a lease is inert to the reclaim; owner-record writes are atomic now, so no kill leaves a partial file). A pre-boot failure retracts the provisional record, so phantom registered projects do not accrue, and fail-fix-rebuild needs no manual `down` anywhere after the lease.

## 0.2.19 (07 November 2026)

- The Windows control daemon's home is locked down at golden install. `C:\`'s default inheritance granted Authenticated Users Modify over `C:\guestd`, including the SYSTEM service binary, so an unprivileged user could replace the binary and ride any service restart to LocalSystem: a harness-made local privilege escalation on the exact machines whose task is local privilege escalation (verified live against a built cell; no transcript shows an agent using it). The install now strips inheritance (SYSTEM and Administrators own the tree, Authenticated Users keep traverse plus Modify only inside `work`, the exec home for profile-less `user=` accounts), deletes the C# sources after the in-guest compile, and the capture scrub asserts the lockdown on every Windows build, so a regression fails the build instead of shipping. The daemon bundle digest is part of the golden derive key, but the derive consumes the PUBLISHED bundle artifact, so the rollout is two commands: `inspect-ranges daemon-bundle` to republish the bundle from the upgraded sources, then `images derive-windows`, which re-bakes on the key miss rather than reusing a vulnerable golden (measured: without the republish the derive cache-hits). Existing goldens stay vulnerable until that runs; rebuilt cells then re-key automatically through the golden digest.

- Agent-created tmux panes are captured. `tmux new-window` or `split-window` typed inside a `terminal` session (the only way an agent gets more panes: send-keys bypasses client prefix handling) used to leave the recording on the original, now-idle pane, so the replay silently undercovered the session. Session open now installs session-scoped `after-new-window` and `after-split-window` hooks (never global: tmux sessions the agent creates wholesale for itself stay untouched) that pipe each new pane into its own sink, named with the session life's token so a reopened name can never append onto a dead life's sink. The hooks install only on a tmux version their pane context is proven on (3.4 or later), both hooks or neither: on an unproven version the hook could bind the wrong pane and divert the session's own tap, so the gate fails closed and keeps the primary capture exactly as it was. The recorder discovers the sinks as they appear (a pane spawned just before close is read whole at stop) and assembles one sibling cast per pane beside the session's own (`terminal-<session>.p<N>`, grouped under the session by its header and carrying the session's tool-call markers), with the same completion-signal scrub. The siblings share the session's store cap: the primary clips to the full cap as before and each sibling takes what remains, down to a header-and-marker stub (the clip previously returned the whole event stream when a budget was already exhausted, a latent defect this budgeting would have exposed). Close removes every sink, per-pane ones included. A session that never spawns panes records byte-identically to before. An agent running its own `pipe-pane` on a hooked pane replaces the tap (one pipe per pane is tmux's rule), the same trust class as the agent killing tmux: the recorder tolerates a sink that stops growing.

## 0.2.18 (07 November 2026)

- A rebuild reclaims a previous run of the same build that died uncleanly, so fail-fix-rebuild is one command. An interrupt, a crash, or a kill mid-phase (the proof boot especially: a failing check invites the Ctrl-C) left the build's project or its `-bx` proof boot registered with containers and a CID lease, and the next build refused with "already holds a lease" or "already running; refusing to supersede" until a manual `inspect-ranges down`. Abandonment takes three signals together: the CID lease is still held (a clean build releases it on the way out), the owner record is marked reclaimable (only the build's own boots declare that, so `up`-booted and `--keep` ranges are refused, never reclaimed), and the recorded owner pid is dead (a live pid is a concurrent build and keeps today's refusals). The reclaimed run's containers go and its lease is released, while its state stays for autopsy, and the reclaim also runs on the cached fast path, where a dead run's proof boot used to keep two VMs running silently behind a green answer. A lease leaked in the seconds before ownership registration is still a manual `down`: nothing proves whose it is.

- `range_friction` reads a sample's transcript with a model, for the apparatus defects that leave no machine signature. `range_apparatus` matches exact signatures and is blind to a file the brief promised and the agent could not find, a credential that did not authenticate, or a terminal that swallowed a newline: those exist only as the agent saying so. Findings carry a category, a confidence, a verbatim quote and the message it came from, and the prompt separates the environment breaking its promises from the task being hard, so an empty list is the expected answer for most transcripts including most that scored zero. It costs a model call per transcript, so it is an after-the-fact audit (`scout scan inspect_ranges/range_friction -T ./logs`) rather than a scorer.

- Every semicolon an agent types through the `terminal` tool now reaches the pane. tmux's client reads a semicolon that terminates an argument as a command separator even after `--`, so it was dropped silently, and the tool's fixed-size chunking manufactured exactly that: a 2000-character boundary landing just after a semicolon. In a real run this corrupted C source written through a heredoc, turning `int non=0;` into `int non=0`, which the pane then reported as the agent's own syntax error. It also broke long blocking sends, whose appended `; tmux wait -S <channel>` splice could lose its own semicolon, leaving the signal to never fire and the send to stall to its timeout and return nothing. Trailing semicolons now go as hex bytes on both the literal and key-name paths. An interior semicolon still rides an ordinary argument, so the ordinary single-command send is unchanged, and `a\;` is byte-exact where tmux used to eat the semicolon and then the backslash.

- A line break in `terminal` keystrokes now reaches the pane as CR rather than LF, the byte a terminal sends when Enter is pressed. Inside the pane's own pty the two are indistinguishable, because the line discipline translates CR to LF before any program sees them, which is why this never showed on a Linux range. A program in raw mode is handed the byte as sent: `ssh` is, and forwards it, and a Windows console on the far side submits on CR and ignores a bare LF, leaving the command typed but unexecuted at the prompt for the next send to concatenate onto. Three Windows sessions in one eval run wedged with exactly that signature, ending past the point where even `exit` worked; `block=True` is refused once `ssh` is the pane's foreground command, so every send into such a session necessarily took this path. Keystrokes carrying no line break are unchanged, so a key name as the whole value is still looked up, and `C-j` still sends a literal LF for a caller that needs one.

  Keystrokes carrying a line break are now typed literally, with tmux key-name lookup off. Lookup is case-insensitive, so a pasted line reading `up`, `end`, `space` or `tab` would otherwise be pressed as that key rather than typed, silently corrupting a pasted wordlist or one-column file.

- The `terminal` echo scrub requires the exact wrap column for each wrapped form of the completion signal, instead of allowing every form one column of trim. Only a wrap on one of the suffix's spaces leaves the line short, because `capture-pane` trims the space, but the allowance also applied to wraps that can never be trimmed: an echo line that simply ended one column short of the pane width with the channel digits read as a wrap inside them, and the next line's leading digits (the first thing `wc -c` prints) were eaten with the match. A wrap continuation must also end with the channel digits, as a genuine one always does, so at the one column where a wrap and a line end look alike, only an output line that is entirely digits can still be mistaken for the signal.

- A `terminal` keystrokes value ending in `;` whose body spells a tmux key name (`up;`, `home;`) is typed, not pressed. The semicolon split sent the remaining body through key-name lookup, which is case-insensitive, so `up;` pressed the up arrow and recalled the previous shell line into whatever the agent was typing. A key name is honored only as the entire keystrokes value, and that includes control spellings: `C-c;` is typed as text too, and pressing the key means sending `C-c` alone.

- The blocking send's completion signal no longer leaks into what the agent reads when the pane wraps on one of its spaces. The scrub already handled a wrap falling anywhere inside `; tmux wait -S <channel>`, but it modelled the wrap as a newline inserted at column 160, and `capture-pane` also trims each line's trailing whitespace: a wrap landing on a space ends the line a column short with the space gone, so `; tmux wait -S ...` comes back as `; tmux wait\n-S ...`. Four of the suffix's split points were affected, and two agents in one eval run were shown the harness marker as if they had typed it.

## 0.2.15 (03 November 2026)

The pre-capture scrub now deletes the file unconditionally and asserts the removal: the daemon credential file never rides a realized disk. A realized image that needs named-user exec when consumed re-creates the file at boot.

Sysprep leaves the account disabled on client Windows while the seed still sets its password every boot, so the documented account (deliberate scenario content: ranges authenticate in-guest with it) was silently unusable on client clones; a credentialed logon failed with "account is currently disabled". Idempotent on server, where the account is already active. Seeds render per boot, so golden-backed clones pick the fix up on their next boot; a realized image captured from a client golden before this fix keeps the disabled account (specialize does not re-run on consumer boots) and needs a rebuild.

- Builds gate each Windows guest's first recipe on setup completion (a new `oobe-settle` stage beside `network-settle`). On a client's first boot from a sysprepped golden, OOBE keeps running about ten minutes past daemon readiness, and its completion step silently undoes exactly the work recipes do in that window: it clears the LSA `DefaultPassword` secret and resets account and logon material, so an autologon or account a recipe set up vanished before capture (measured). The gate polls `ImageState` until `IMAGE_STATE_COMPLETE` (20-minute bound, `oobe_settle` and `oobe_settle_timeout_s` build options) and is instant on realized images and servers, whose state is already complete.

- `doctor` reads installed (Windows) goldens against the Windows install recipe version instead of misreading them as stale against the Linux recipe version, gives a stale Windows golden its own re-derive guidance, and skips imported images, which have no recipe to compare against.

- The readiness failure names each failed guest's own probe window. A guest's declared boot budget extends the shared window, so reporting only the shared number misstated how long a slow guest was actually given.

- Client Windows goldens bake Windows Update off at install: the `NoAutoUpdate` policy plus disabled `wuauserv`/`UsoSvc` start. On client media WU patches and auto-restarts at variable times, which kills builds mid-recipe and makes clone content drift with the patch cadence. The Windows install recipe version moves to 5 (existing goldens re-derive on next use); servers keep their stock behavior.

- The range container image can draft off the configured registry: with `INSPECT_RANGES_RANGE_IMAGE` unset and `INSPECT_RANGES_REGISTRY` explicitly set, `up` resolves the location's convention name `range` at the engine-version tag (a tag inside a single-repository location, the hub form's `<name-prefix>-range` repository (exactly the catalog's published name), or `<prefix>/range` elsewhere) and uses the digest it resolves to, never the mutable tag, so the no-mutable-tag posture holds end to end. The explicit pin always wins; the default search path never drafts (a pin-less dev host keeps building locally); a missing convention ref logs the attempt and falls back to the local build. One registry value now configures a fleet completely.

## 0.2.13 (02 November 2026)

- `hardware: {firmware: uefi-secure, tpm: true}` is realized: Secure Boot guests get the MS-key-enrolled OVMF build (`secure='yes'`, SMM on, per-guest nvram copied from the enrolled VARS template, q35 only, refused `hardware-secure-requires-q35` otherwise) and `tpm` adds a per-guest swtpm 2.0 the range container's libvirt manages (state is per-boot: nothing may seal disk secrets to it). Windows guests now accept exactly these two knobs, the Windows 11 contract, while the rest of the hardware block stays refused there (the tier owns its measured device model). The range image gains `swtpm` (run as libvirt-qemu:kvm; a TPM guest's QEMU runs as that shared principal instead of a per-VM uid, since libvirt holds the swtpm control socket at 0600 to its owner and the hardened container has no relabel slot; the trade stated plainly: TPM guests are not isolated from one another at the VMM layer, so a VMM escape in one reaches every other TPM guest's process, disk, emulated TPM, and the swtpm local CA (non-TPM guests keep their per-VM-uid bound, and nothing is agent-reachable without that escape first)). Verified live: an ubuntu guest under the enrolled keys reports SecureBoot enabled from its own efivars and exposes a working TPM 2.0 at /dev/tpm0.

- Windows 11 goldens: `images derive-windows --os 11` installs a Windows 11 client golden through the same one-shot hardened flow, under the contract setup verifies (q35, the MS-key secure loader with SMM, an emulated TPM 2.0, a GPT/ESP disk layout, w11 virtio drivers, the Pro image selected by index with the documented edition-selection key); the OS variant enters the derivation key, and the install bound is a per-variant fact. The installer answers every measured client-OS trap: boot-prompt keypresses gate on the install cdrom's read counter (a stray space presses setup's Cancel and a quit-confirm modal blocks the restart), the OOBE wizard is skipped outright, `BypassNRO` covers the deliberately network-less install VM, device encryption is prevented at both registry points (sysprep refuses an encrypting volume), and the client's DISABLED built-in Administrator activates and takes its password at specialize (so cmd-hostile admin passwords refuse up front). Verified live: a clone boots the production pipeline and reports Secure Boot enabled, the TPM ready, and the Pro edition from inside the guest, with exec as SYSTEM over vsock. A `version: "11"` Windows host must declare `hardware: { firmware: uefi-secure, tpm: true }`, the shape its golden installs under (refused `windows11-hardware-required` otherwise). Windows golden sidecars now record `kind: installed` explicitly rather than riding the `.iso`-suffix fallback, and the daemon bundle's Windows installer selects its virtio driver directory by the running OS (client w11, server 2k22; the daemon bundle version bumps in lockstep).

- `oracle.alive(guest)`: VMM-process liveness for any guest, daemon-managed or opaque, observed from the driver (`virsh domstate` for QEMU guests, the recorded pidfile for Cloud Hypervisor ones) through a seam every oracle-reaching construction path injects (the provider, `range_oracle` attach, and the build's proof boot). The denial-of-service scoring primitive: goal types can now assert an appliance died or survived without any in-guest access. QEMU states `paused`, `pmsuspended`, and `in shutdown` count as alive (a reversible nap is deliberately not a kill, so an in-guest suspend cannot game a DoS goal); Cloud Hypervisor pidfiles are verified against the process's comm so pid recycling cannot read alive-when-dead. Unknown guests refuse; a missing seam refuses rather than guessing (unit fixtures, and separated host backends, where the range's docker is remote and a local probe would read every guest dead); failure to observe reads as not-alive, never an exception, which also means an externally realized attack box reads not-alive (goals score appliances, not the attack box).

- The exec witness (per-guest `execve` evidence) is hardened and its record made honest. The daemon now accepts only genuine kernel process-connector messages (sender `nl_pid` 0), so an in-guest process — even as root — can no longer forge `execve` records through it; combined with the daemon's unprivileged-by-default execution identity, an agent must first earn root (itself witnessed) before it can interfere. A daemon restart is now detected by a boot-session change carried on every `exec_events` reply, closing a window where a restart whose sequence had already passed the cursor went unrecorded. A kernel subscriber overflow (`ENOBUFS`) is recorded as an unknown-size gap rather than a false event count (the kernel reports overflow episodes, not lost events); a ring overwrite keeps its exact count. Event `ts_ms` is documented as the host-ingest wall-clock time it has always been (not the connector's monotonic timestamp). The `exec_events_result` reply carries an optional `session` field (protocol unchanged, optional on decode); the daemon version is `3.5.0` (also reconciling the bundle label, which trailed the daemon at `3.3.0`).

- The guest daemon (`vsockd`) now fails closed instead of silently running the agent as root when it cannot drop to the unprivileged `agent` user. Default-identity exec and file operations on a root daemon whose image is missing the `agent` account are refused (`EACCES`) rather than run with root's reach; an explicit `user=` is unaffected, and an unprivileged daemon (dev/CI, no root to hand out) stays tolerant. The pong reply additionally reports the daemon's default-exec identity, and `up` refuses a dedicated attack box (the foothold) whose daemon would run the agent as root — a privilege-escalation task must not start already solved. A daemon predating the new pong field reports no identity and is left to the daemon's own guard. Protocol version is unchanged (the field is optional on decode); the daemon version is `3.4.0`.

- `up --from-spec` and the attack-box conformance battery (`inspect-ranges attackbox verify`) no longer require the attacker's image in the cache when a provider supplies the attack box (`INSPECT_RANGES_ATTACK_BOX`). Both render the bundle to a temporary directory and realize it once with the provider already resolved, which boots the dedicated attack box instead of pulling its image locally, so the self-sufficiency cache check previously forced a download the run never used. The check still holds for every other guest and for bundles `inspect-ranges render` writes, which may later run without a provider and must stay self-sufficient.

- Isolated `dhcp: true` networks now advertise the bridge's service address as a dead-end router option in every lease: some appliance DHCP clients refuse to program a lease that carries no router option (observed live porting a management-plane appliance whose client logged `dhcp-address-assigned` and then installed nothing). The address answers nothing and routes nowhere, so isolation is unchanged; this is the same lease shape libvirt and slirp present. Linux guests on such segments gain a dead-end default route they previously lacked.

- Attack box: an external provider can be a pinned program rather than an installed Python package (`INSPECT_RANGES_ATTACK_BOX=inspect_ranges._attackbox.pinned.pinned_attack_box:<pin file>`). A deployment-written pin file names one release by tag, source-tarball URL, and SHA-256; the first use downloads the tarball, verifies the digest before extracting anything, caches the release per user, and runs `<program> attackbox boot|teardown|probe` over a versioned JSON protocol with the tap fds passed at the numbers the request names. Eval init fetches and probes beside the catalog image pull and refuses with the program's own cause and remedy when the host cannot boot a box; the recorded origin carries the pin's contents, not its path, so `down` and the reaper tear a box down with the release that booted it. `INSPECT_RANGES_ATTACK_BOX_PROGRAM` names an installed copy for offline hosts. The default is unchanged: with the variable unset, the realizer boots the built-in box.

- Goal types are now inspect-ai registry citizens: the new `range_goal` decorator registers a `GoalType` subclass in the shared registry (the `range_goal` kind) at class definition, replacing the bare `register_goal_type(...)` call sites (the function remains for programmatic use). A type defined beside its task registers when the task loads; a type in an installed package registers as `pkg/name` and self-discovers from that reference through the package's `inspect_ai` entry point, with bare-suffix resolution while unique and a loud refusal listing candidates on a cross-package collision. Requires inspect-ai 0.3.287 or newer (the release carrying the `range_goal` registry kind).

- Distribution: a blob download that fails mid-transfer (a TLS record failure, a reset connection, a body cut short of its declared length) restarts from the beginning, up to four attempts with a short backoff, before surfacing as a coded `registry-unreachable` refusal that names the registry and the last fault. Content addressing makes the restart safe, and the digest check still runs on the final body, so a mismatch at full length (tampering or a wrong descriptor) is refused immediately rather than retried. Previously a single fault in a multi-gigabyte golden stream failed the whole pull, and a truncated body read as a digest mismatch because `http.client` ends a short `Content-Length` body quietly.

## 0.2.6 (31 October 2026)

- Fixes a 0.2.5 regression that failed every range boot on common kernels: the bridged-frames accepts used `meta ibrname`/`obrname` in the `inet` family table, and bridge meta is bridge-family-only on most kernels, so `nft -f` refused the ruleset ("Operation not supported") and the range container exited before anything booted. The same semantics load everywhere as a plain interface-name pair: at the IP-layer hook br_netfilter presents a bridged frame with the segment bridge as both devices, so `iifname "br-x" oifname "br-x" accept` is exactly "entered and left through this bridge", per bridge as before, with routed frames still meeting the egress policy. Verified by loading the rendered ruleset and exchanging same-segment traffic on a host with `br_netfilter` active.

## 0.2.5 (31 October 2026)

- The normalized spec hash excludes defaulted values: adding a schema field whose default reproduces prior behavior no longer moves any existing spec's hash, so build manifests, published builds, and default project names survive vocabulary-widening engine upgrades. The soundness rule ships with it: defaults are frozen contracts (a shipped default's meaning never changes; new behavior arrives behind a new field or an explicitly declared `schema_version`), pinned by a recorded snapshot of every shipped default and a golden hash of a canonical spec. One-time migration: this change itself moves every spec hash once (existing build manifests read `range-not-built` until their ranges rebuild, and the published examples republish with this release), after which schema additions stop paying that cost.

- Hosts can declare `nested_virtualization: true` (the guest runs KVM virtual machines of its own, e.g. kernel-under-test workloads). The declaration is enforced rather than assumed: planning refuses it under a named `cpu_model` (`nested-virt-requires-host-passthrough`), `up` refuses at a new `preflight` stage on a host whose KVM does not expose nesting, `plan` reports the requirement, and `doctor` gained a `nested kvm` row. Thanks to the default-insensitive normalized form (above), the new field moves no existing spec hash; a bundle that declares the flag needs this engine or newer (older engines refuse its `boot.json` fail-closed), while undeclared new bundles stay readable by older engines (the flag is emitted only when set).

- New command `inspect-ranges shell <project> [guest]`: an interactive operator shell on a guest of a running range, as a tmux session driven entirely over the range's control channel, so it needs no SSH and no guest listener and works on fully isolated networks. It attaches only to ranges booted with `inspect-ranges up`: a project booted by the Inspect sandbox provider refuses by recorded origin, so an eval sample can never acquire an interactive operator mid-run. Guest output is treated as untrusted and filtered before it reaches the operator's terminal (clipboard-write and palette OSC sequences and all device-control strings are dropped; display sequences and titles pass). Sessions survive detach (`Ctrl-]`) for reattach by the same name; `--user` picks the guest identity (default: the daemon identity, root on Linux); `--cast` records the attach as a local asciicast. Linux guests only. The provider's `connection()` message now points operators at `shell` instead of a recorded follow-up.

- Range networking on hosts with `br_netfilter` loaded (Docker hosts, Amazon Linux among them): frames bridged within one segment were diverted through the range namespace's default-drop forward chain, since every new network namespace starts with `bridge-nf-call-iptables=1`, so same-segment guests could resolve each other's addresses but exchange no IPv4 packet (an attack box saw every target port filtered). The forward chain now accepts a frame that enters and leaves through the same segment bridge, one rule per bridge, ahead of the egress policy; a routed frame has at most one bridge side and still meets that policy.

- New example `defender_ops` (original): king-of-the-hill sabotage of a small ops environment (status-board tamper, orderboard degrade, watchdog crash-by-address) while the bastion gate must stay up, then a quiet patch-and-cleanup scored from the exec witness and the exported ops log.
